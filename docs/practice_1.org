* 1. Provide the diﬀerent features that the system should meet.
The system should meet the following features:
- *Confidentiality*: only the person with the key can access the information.
- *Identiﬁcation or authentication of the entity*: making sure the user trying to decrypt the information is the right person.
- *Authorization*: Deciding whether you have the right to access the data and granting the right permissions.
- *Data integrity*: Checking if the data wasn't altered somewhere.
- *Signature*: It links a specific person to a given data ensuring that the person cannot later claim "I didn't send this".

* 2. Identify and characterize the diﬀerent entities that interact in the system and describe their main features.
- *User*: person providing data to encrypt or person wanting to decrypt the data.
- *Administrator*: system manager that coordinates access.
- *Symmetric encryption algorithm*: the main algorithm responsible for encrypting and decrypting the data.
- *Public key encryption algorithm*: responsible for encrypting and decrypting the key which the main algorithm uses.
- *Authentication algorithm*: verifies the identity of the user and passes that information to the administrator.

* 3. Describe the provisional design of the project and explain how the information can be accessed only by the authorized users.
The provisional design is based on a hybrid cryptographic architecture[span_0](start_span)[span_0](end_span).
- *Data Encryption*: The Symmetric Encryption Algorithm is used to efficiently encrypt the original Data, producing the Encrypted Data[span_1](start_span)[span_1](end_span).
- *Key Encapsulation*: The Public Key Encryption Algorithm is used to securely encrypt the symmetric session key[span_2](start_span)[span_2](end_span).
- *Identity Verification*: The Authentication Algorithm is utilized by the Administrator to verify the User's identity before processing requests[span_3](start_span)[span_3](end_span).

The information can be accessed only by authorized users because the Administrator strictly controls the access flow through the Authentication Algorithm[span_4](start_span)[span_4](end_span). Even if unauthorized entities intercept the Encrypted Data, they cannot read it without the symmetric key. This key is secured by the Public Key Encryption Algorithm and can be decrypted exclusively by the authorized User possessing the corresponding private key[span_5](start_span)[span_5](end_span).
